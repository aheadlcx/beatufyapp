# 滤镜实现原理（写给没有 OpenGL ES 基础的 Android 开发者）

本文对应 `Shaders.FS_FINAL` 里的 `applyFilter()` 函数。读完你就能看懂现有 12 个滤镜，并且能自己加第 13 个。

---

## 0. 预备知识：只需要懂三个概念

### 0.1 一张图就是一个二维数组

一张 1080×1920 的图，就是 1080×1920 个"像素"排成的网格，每个像素是 `(r, g, b)` 三个 0~1 之间的小数（`1.0, 1.0, 1.0` = 白色，`0,0,0` = 黑色，`1,0,0` = 红色）。

### 0.2 UV 坐标：用 0~1 表示"画布上的位置"

GPU 不用"第 357 行第 89 列"来描述位置，而是用**比例**：

```
(0,0) ─────────── (1,0)
  │                 │
  │     uv 坐标      │     u = 横向位置（0=最左，1=最右）
  │                 │     v = 纵向位置（0=最下，1=最上）
(0,1) ─────────── (1,1)
```

### 0.3 片元着色器：一个"每个像素各跑一遍"的函数

普通代码是"输入一批数据，循环处理"。GPU 反过来：**你写一个只处理单个像素的函数，GPU 自动对画面上的每个像素各调用一次**（几百万次，但全部并行，所以极快）。

我们项目里所有滤镜，本质上就是 `Shaders.FS_FINAL` 里的这个函数：

```glsl
vec3 applyFilter(vec3 c) {   // c = 当前像素的颜色 (r,g,b)
    vec3 f = c;
    if (uFilter == 1) { ... }      // 判断当前选了哪个滤镜
    else if (uFilter == 2) { ... }
    ...
    return mix(c, clamp(f, 0.0, 1.0), uFilterStrength);  // 与原图按强度混合
}
```

`mix(a, b, t)` 是 GLSL 内置的线性插值：`t=0` 返回 a，`t=1` 返回 b，中间按比例混合。**滤镜强度滑杆就是靠最后这一行 mix 生效的**——每个滤镜先算出"完全体"效果 f，再和原图按滑杆比例混合。

## 1. 六个通用套路（理解了它们就看懂了所有滤镜）

| 套路 | 做法 | 用途 |
|---|---|---|
| **提亮** | 每个通道加常数：`c + 0.05`，或乘系数：`c * 1.1` | 白皙、蜜桃 |
| **色调** | 给不同通道乘不同系数：`vec3(r*1.09, g*1.03, b*0.92)` → 红绿多蓝少 = 暖 | 暖阳、冷调 |
| **去色** | `lum(c) = 0.299r + 0.587g + 0.114b`（人眼对绿色最敏感，所以权重不是 1/3） | 黑白 |
| **低饱和/保色调去色** | `mix(vec3(lum), c, 0.9)`：往灰度方向收一点但保留色彩 | 白皙、粉黛 |
| **对比度** | `pow(c, 0.9)`（指数<1 提亮暗部）或 S 形曲线 `c*c*(3-2c)`（暗的更暗亮的更亮） | 胶片、粉黛 |
| **暗角** | 离画面中心越远越暗：`c *= 1 - 0.3 * d²`，d 是到中心 (0.5,0.5) 的距离 | 胶片 |

## 2. 逐个滤镜拆解

### 1. 白皙（uFilter == 1）
```glsl
f = c * 1.10 + 0.03;            // 整体提亮 10% 再加一点常数（加常数对暗部提升更明显）
f = mix(vec3(lum(f)), f, 0.92); // 轻微降低饱和度（往灰度方向收 8%）
```
**原理**：乘法提亮高光、加法提亮阴影，两者叠加让画面整体白净；再轻微去饱和，接近"冷白皮"的观感。

### 2. 暖阳（uFilter == 2）
```glsl
f = vec3(c.r * 1.09, c.g * 1.03, c.b * 0.92) * 1.05;
```
**原理**：红通道放大、蓝通道缩小 = 画面偏暖（日落色调），最后整体 ×1.05 轻微提亮。

### 3. 冷调（uFilter == 3）
```glsl
f = vec3(c.r * 0.94, c.g * 1.00, c.b * 1.09);
```
**原理**：暖阳的镜像——压红抬蓝，画面偏冷（清晨色调）。

### 4. 胶片（uFilter == 4）
```glsl
f = mix(c, c * c * (3.0 - 2.0 * c), 0.4);  // S 形曲线：对比度加强
float d = length(vUV - 0.5);               // 当前像素到画面中心的距离
f *= 1.0 - 0.30 * d * d;                   // 暗角：越靠边越暗
f.b += 0.02;                               // 微微加蓝（胶片褪色感）
```
**原理**：`c*c*(3-2c)` 是"平滑阶跃函数"，对暗像素输出更暗、亮像素更亮，中调几乎不变——这就是摄影里的"S 曲线"对比度。暗角（vignette）模拟老镜头边缘失光，`d²` 让衰减只在边角明显、中心几乎无损。

### 5. 初恋（uFilter == 5）
```glsl
f = vec3(c.r + 0.05, c.g + 0.02, c.b + 0.04);  // 整体轻提亮，红蓝多加一点
f = mix(vec3(lum(f)), f, 1.08);                 // 注意：系数 >1 = 增饱和
```
**原理**：`mix` 的第三个参数超过 1 时是"过饱和"（拉离灰度方向）。轻提亮 + 微增饱和 = 粉嫩通透的初恋感。

### 6. 黑白（uFilter == 6）
```glsl
f = vec3(lum(c));   // 三个通道都设成同一个亮度值
```
**原理**：人眼对绿光最敏感、蓝光最不敏感，所以亮度公式是 `0.299r + 0.587g + 0.114b`（这正是彩色电视转黑白的国际标准 ITU-R BT.601）。直接把 rgb 都写成这个值就是灰度图。

### 7. 复古（uFilter == 7）
```glsl
f = vec3(lum(c)) * vec3(1.14, 1.0, 0.82);   // 先转灰度，再给灰度图染色：偏黄
f = mix(c, f, 0.85);                        // 保留 15% 原图色彩
```
**原理**：老照片 = 灰度 + 泛黄。做法是"去色后再乘一个颜色"——乘 `vec3(1.14, 1.0, 0.82)` 表示染色时红多蓝少（sepia 棕褐色调）。保留一点原图色彩是为了不显得死灰。

### 8. 粉黛（uFilter == 8）
```glsl
f = vec3(c.r + 0.06, c.g * 0.97 + 0.01, c.b * 0.96 + 0.04);  // 加红压蓝 = 粉调
f = mix(vec3(lum(f)), f, 0.9);
f = pow(clamp(f, 0.0, 1.0), vec3(0.92));                     // gamma 提亮
```
**原理**：`pow(c, 0.92)` 对 0~1 的数来说，指数 <1 会**提亮暗部**（0.25 → 0.28，0.81 → 0.83），这就是摄影里的 "gamma lift"，让画面呈现朦胧的低对比感。配合粉色调 = 日系"粉黛"。

### 9. 蜜桃（uFilter == 9）
```glsl
f = vec3(c.r * 1.07 + 0.03, c.g * 0.99, c.b * 0.95 + 0.02);
f = mix(vec3(lum(f)), f, 1.05);
```
**原理**：比"粉黛"红得多、不压对比度——红通道放大约 7% 再加常数，模仿蜜桃表皮的暖粉反光。

### 10. 冷蓝（uFilter == 10）
```glsl
f = vec3(c.r * 0.92, c.g * 1.0, c.b * 1.12) * 1.03;
```
**原理**：比"冷调"更极端的压红抬蓝（蓝通道 +12%），并且整体提亮，制造"月光/冰感"。

### 11. 森系（uFilter == 11）
```glsl
f = vec3(c.r * 0.92 + 0.01, c.g * 1.06 + 0.02, c.b * 0.94);
f = mix(vec3(lum(f)), f, 0.95);
```
**原理**：压红蓝、抬绿——把画面色温往绿色偏移，模拟树荫下的环境色（森系写真的核心就是环境绿）。

## 3. 强度滑杆是怎么生效的

`applyFilter()` 的最后一行：

```glsl
return mix(c, clamp(f, 0.0, 1.0), uFilterStrength);
```

- `f` 是滤镜的"完全体"效果；
- `uFilterStrength` 是滑杆值 0~1；
- 滑杆拉到中间时，你看到的 = 50% 原图 + 50% 滤镜。

所以**新增滤镜不需要考虑强度问题**，只要把完全体写对，混合是免费的。

## 4. 动手：添加一个新滤镜

以添加"日落"（橙色渐变）为例，四步：

**① `BeautyParams.FILTER_NAMES` 加名字**：
```java
public static final String[] FILTER_NAMES = {..., "日落"};
```

**② `Shaders.FS_FINAL` 的 `applyFilter()` 加分支**（uFilter == 12）：
```glsl
} else if (uFilter == 12) {
    // 上蓝下橙的渐变：vUV.y 从 0(下) 到 1(上)
    vec3 sunset = mix(vec3(1.0, 0.45, 0.15), vec3(0.25, 0.3, 0.65), vUV.y);
    f = mix(c, sunset, 0.35);   // 35% 强度往日落色上靠
}
```

**③ 没有了。** UI 的滤镜列表由 `FILTER_NAMES` 驱动自动生成，强度滑杆免费获得。

**④ 真机看效果，微调系数**——滤镜调色本质是"凭眼睛调系数"，上面的数字都是这个流程调出来的起点。

## 5. 常见疑问

**Q: 为什么 clamp 到 0~1？**
GPU 的纹理格式是 8bit/通道，超过 1 的值会被截断。运算中间不 clamp 可能得到负数或 >1，最终写进纹理前必须夹回来（`applyFilter` 返回前统一做了）。

**Q: 为什么数值运算用 vec3 而不是分别写 r/g/b？**
`vec3` 的乘法/加法是逐分量的（`a * b` = 三个分量各自相乘），一行顶三行，也让 GPU 走向量化执行。

**Q: 滤镜之间会互相影响吗？**
不会，`uFilter` 是 int，一次只命中一个分支。滤镜与磨皮/美白等基础美颜是**串联**的：先做磨皮美白，最后才套滤镜（所以滤镜作用在"已经美颜过的画面"上，所见即所得）。

**Q: 为什么有的滤镜里出现 `vUV`？**
`vUV` 是当前像素在画面里的位置。用到它的滤镜都是"空间相关"效果（胶片的暗角、想象中的日落渐变），而纯调色滤镜只依赖像素自己的颜色 `c`。
