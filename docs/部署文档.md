# BeautyCamera 直播系统部署文档

本系统基于 WebRTC 实现手机直播推流与多端观看。本文面向"从零部署到跑通"的完整流程。

---

## 1. 系统组成

```
┌─────────────────────┐
│ 信令服务器 (Node.js) │  server/server.js —— 只转发信令（offer/answer/ICE/弹幕）
│  零依赖，单文件       │  不转发音视频（媒体 P2P 直连）
└─────────┬───────────┘
          │ WebSocket (JSON)
   ┌──────┴───────┬──────────────────┐
   │              │                  │
Android 主播     Web 观众           Android 观众
(live/ 模块)    (server/web/)      (live/ 模块观看模式)
```

- **媒体路径**：主播与观众之间 P2P 直连（UDP，经 STUN 打洞），服务器只承担信令，
  单台 1核1G 服务器可支撑数千房间。
- **核心实时逻辑（C++）**：`live/src/main/cpp/livecore.cpp` —— 帧级统计与 AIMD
  自适应码率控制，编译为 `liblivecore.so`，随 APK 分发。
- **编解码（C++）**：libwebrtc（`io.getstream:stream-webrtc-android` 预编译库）。

## 2. 信令服务器部署

### 2.1 局域网/本机（开发调试）

```bash
cd server
node server.js 8080        # 绑定 0.0.0.0，无需 npm install
```

验证：浏览器打开 `http://<本机IP>:8080/web/` 能看到直播页面即成功。

### 2.2 公网 VPS（推荐生产用法）

1. 任一有公网 IP 的 Linux VPS（1核1G 起步，Ubuntu/Debian/CentOS 均可）；
2. 安装 Node.js ≥ 18：`apt install nodejs` 或 [官方二进制包](https://nodejs.org/)；
3. 上传 `server/` 目录（只需 `server.js` 与 `web/`），启动：
   ```bash
   nohup node server.js 8080 > server.log 2>&1 &
   # 或配置 systemd 服务（见下）
   ```
4. 防火墙/安全组放行 **TCP 8080**；
5. 验证：外网浏览器访问 `http://<VPS公网IP>:8080/web/`。

systemd 服务示例（`/etc/systemd/system/live-signal.service`）：

```ini
[Unit]
Description=WebRTC signaling server
After=network.target

[Service]
ExecStart=/usr/bin/node /opt/live/server.js 8080
Restart=always
User=nobody

[Install]
WantedBy=multi-user.target
```

### 2.3 生产加固（可选，正式运营前建议）

| 项 | 做法 |
|---|---|
| 加密信令 | Nginx/Caddy 反代 + TLS 证书，客户端地址改 `wss://`；同时删除 Android Manifest 里的 `usesCleartextTraffic` |
| 鉴权 | `join` 消息加 token 字段，服务器校验（当前为开放房间，任何人可开播/观看） |
| 房间白名单 | `handleJoin` 中校验 roomId |
| TURN 服务 | 双方都在严格 NAT 后时需要（见 §6） |

## 3. Android 端（主播 / 观众）

### 3.1 安装

安装 `BeautyCamera_*.apk`（内含 `:live` 直播模块）。系统要求 Android 7.0+。

### 3.2 权限

首次开播会动态申请 **相机** 与 **麦克风**。
⚠️ 若在"系统设置"中手动授权后返回，app 会自动继续（已处理该场景）。

### 3.3 开播（两种模式）

进入 app → 点左上角 **直播** → 填写信令地址与房间号：

| 模式 | 按钮 | 说明 |
|---|---|---|
| 摄像头开播 | 开播(主播) | 采集相机+麦克风真实推流 |
| 图片轮播开播 | 开播(轮播图片) | 推送 3 张程序生成的轮播图（无摄像头环境/联调用） |

信令地址写法：
- 模拟器：`ws://10.0.2.2:8080`（10.0.2.2 = 宿主机）
- USB 连接的真机：先 `adb reverse tcp:8080 tcp:8080`，再填 `ws://127.0.0.1:8080`
- 局域网/公网：`ws://<服务器IP>:8080`（公网建议 wss）

### 3.4 观看

填同一信令地址与相同房间号 → 点 **观看(观众)**。主播开启后自动收到画面。

## 4. Web 端（主播 / 观众）

浏览器打开 `http://<信令服务器>:8080/web/`：

- **开播（图片轮播）**：canvas 轮播 3 张图片（2s/张）作为视频源推流；
- **观看**：收流渲染到 `<video>`。

Web 端与 Android 端完全互通（同一信令协议、同一房间）。

## 5. 联调验证矩阵（本次已完成）

| # | 主播 | 观众 | 结果 |
|---|---|---|---|
| 1 | Android（图片轮播，模拟器） | Web（Edge 浏览器） | ✅ 收到画面（180x320，pc=connected） |
| 2 | Web（图片轮播，Edge 浏览器） | Android（模拟器） | ✅ 收到画面（"图片 3·绿色"渲染成功） |
| 3 | 信令协议 | Node 测试客户端（test-viewer.js） | ✅ offer/ICE 候选完整转发 |

已实测的健壮性行为：
- 主播进程被杀后重启，重新 join 同房间会**抢占**旧会话；
- 观众端断线重连（3s 退避）后自动重新入房；
- 服务器 30s 心跳探测，90s 无响应的半开连接自动清理。

## 6. 常见问题排查

| 现象 | 原因与处理 |
|---|---|
| "CLEARTEXT communication not permitted" | 明文 ws:// 被系统拦截。demo 已放行；生产请改 wss:// |
| 观众加入后主播无反应 | 查服务器 `signaling.log` 是否有 `offer for xxx: forwarded`；若无，主播与服务器信令已断（看是否出现 replaced/心跳踢出） |
| 信令通但画面黑 | ICE 未打通：双方交换的候选里若只有各自的私有地址（如 10.0.2.15 / 192.168.x.x），需部署 TURN 服务器（coturn），并把地址加进两端 iceServers |
| 模拟器上卡顿/ANR | SwiftShader 软渲染 + libwebrtc 负载大，属模拟器性能限制，用真机验证 |
| 华为真机看不到 logcat | 系统过滤三方 app 日志，用屏幕上的调试信息（statusView/chatView）排查 |
| 模拟器 WebRTC 收不到流 | 确认使用较新模拟器（31+，支持 WebRTC 回环候选）；或改用真机+真机 |

## 7. 生产化路线（当前 demo → 商用）

1. **SFU 替换 mesh**：观众数 >10 后，主播上行带宽成为瓶颈。选型：
   [LiveKit](https://livekit.io/)（开源、文档好）、mediasoup（Node）、Janus（C）。
   信令协议可沿用，仅替换转发拓扑；
2. **TURN**：coturn 部署 + 静态密钥鉴权，覆盖严格 NAT 用户（约 10-20% 场景）；
3. **录制与回放**：SFU 侧 RTP 转 RTMP/HLS 存储对象存储；
4. **鉴权与房间管理**：token 签发（HMAC/JWT）、房间白名单、开播密码；
5. **监控**：`LiveStats` 快照已含 fps/码率/丢包/RTT，上报到服务端聚合即可做大盘。
